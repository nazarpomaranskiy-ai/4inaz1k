# Moonlight Assistant v0.2.1 — Windows оверлей та аналіз відео

Це експериментальний хелпер, **не автономний бот**. Вона знаходить кольорові об’єкти,
відстежує їх між кадрами й малює рекомендований напрямок короткого ухилення.
Клавіатурою та грою не керує. Модель не навчена на записах RotMG.


## Нове у v0.2: оверлей поверх гри

Потрібні Windows 10 2004+ або Windows 11, Python 3.11/3.12 з Tkinter
(стандартний інсталятор python.org) та віконний/безрамковий режим гри.
Ексклюзивний fullscreen не підтримується.

1. Відкрий гру, вимкни обертання камери, зафіксуй масштаб і положення вікна.
2. Запусти `overlay.bat`. Під час першого запуску відкриється знімок екрана.
3. Калібрування приховає своє вікно й через 5 секунд захопить гру. Якщо гра
   недоступна, знімок не робиться. R повторює захоплення.
4. Виділи прямокутник ігрової області без HUD, потім клікни центр персонажа.
   Унизу є приціл 4×; радіус хітбокса задається вручну. Клік можна змінити.
   Enter або Save підтверджує, Backspace скидає вибір, Esc скасовує.
5. Оверлей пропускає кліки у гру. **F8** — пауза, **F9** — вихід.
6. Для повторного калібрування запусти `calibrate.bat`.

Новий профіль зберігається у `live_config.json`. Зміна позиції вікна, розміру,
масштабу, монітора або центрування персонажа потребує повторного калібрування.
За замовчуванням розпізнаються тільки червоні снаряди: налаштуй `bullet_hsv`
та інші параметри у `live_config.json`. Автоматичного визначення персонажа,
геометрії арени, стін, кольорів снарядів та фаз поки немає.

Зелена стрілка — найкращий з перевірених коротких прогнозів, а не гарантія
безпечного руху. Тонкі промені — оцінки інших напрямків. Це **не повна карта
безпечних хвиль**. Реакція людини, зміни швидкості, рух камери, нові снаряди
й нелінійні траєкторії можуть зробити рекомендацію неправильною.

Оверлей виключає власне вікно із захоплення через Windows Display Affinity;
якщо Windows відхиляє цю операцію, запуск припиняється. Якщо кадр застарів більш
ніж на 200 мс, стрілка приховується. Захоплення й аналіз працюють в окремому
потоці, з цільовою частотою до 30 кадрів/с. Фактична швидкість залежить від ПК.

Для другого монітора: `overlay.bat --calibrate --monitor 2`, потім
`overlay.bat --monitor 2`.

### Збір даних для майбутнього навчання

Запусти `overlay.bat --record`. До `sessions/дата-час/` зберігатимуться лише
кадри вибраної області арени (до 5/с), калібрування й `observations.jsonl`.
F8 призупиняє і захоплення, і запис. Дані залишаються локально.

Це **не самонавчання**: у записах `label: null`, немає достовірної інформації
про натискання, влучання, HP чи успіх проходження. Наступний етап — розмітка
пропущених снарядів і влучань, перевірка на відкладених записах, після чого
можна покращувати детектор та порівнювати стратегії. Поточна версія не підмінює
цей етап заявою про навченого бота і не керує WASD.

На Windows перевірені створення прозорого вікна, виключення із захоплення
та GUI-калібрування на синтетичному знімку (приховане вікно, вибір області,
координати персонажа, збереження). Також перевірені математичний прогноз,
розпізнавання синтетичних кадрів, оцінка швидкості й перетворення координат.
Надійність рекомендацій у бою RotMG ще не перевірена.

## Windows: офлайн-аналіз запису

1. Встанови Python 3.11 або 3.12 із python.org (з Python Launcher).
2. Розпакуй папку. Перетягни MP4 на `run.bat` або запусти `run.bat video.mp4`.
3. Відкрий `annotated.mp4`; поруч буде `annotated.csv` з оцінками кожного кадру.

Перший запуск встановлює залежності через інтернет. Налаштування в `config.json`
обов’язково треба пристосувати до запису: надані значення — приклад для 1280×720
із червоними снарядами, а не перевірений профіль Moonlight Village.

Щоб отримати перший кадр для вимірювання координат:

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe analyze.py video.mp4 --snapshot first.png
```

## Калібрування

- `frame_size`: ширина й висота відео. Невідповідність зупиняє аналіз.
- `arena`: прямокутник ігрової області `[ліво, верх, право, низ]` без інтерфейсу.
  Внутрішні перешкоди поки не моделюються.
- `player`: координати центра хітбокса. Версія передбачає, що персонаж залишається
  в цій точці на екрані. Ручне обертання, зум і зсув камери спотворюють оцінки.
- `player_radius`: радіус хітбокса у пікселях; `player_speed`: швидкість у пікселях/с.
  Вимірюй за зміщенням об’єктів відносно персонажа при русі; уповільнення та інші
  зміни швидкості ця версія не враховує.
- `bullet_hsv`: список пар нижньої/верхньої межі кольору в OpenCV HSV
  (`H: 0–179`, `S,V: 0–255`). За замовчуванням розпізнається лише яскравий червоний.
  Різнокольорові снаряди потребують додаткових діапазонів. HUD, декорації й ефекти
  того самого кольору можуть давати помилкові спрацьовування.
- `min_area`, `max_area`: площа контуру снаряда у пікселях².
- `ignore_rectangles`: області, які слід виключити, у форматі `arena`.
- `horizon`: час прогнозу в секундах. `margin`: додатковий запас у пікселях.
- `tracking_gate`: максимальна похибка зіставлення між кадрами у пікселях.

Жовті кола — виявлені об’єкти, сині відрізки — оцінка швидкості, стрілка біля
персонажа — рекомендація. `UNKNOWN` означає недостатньо даних; `NO SAFE CANDIDATE`
означає, що всі перевірені допустимі дії прогнозують зіткнення. Додатна оцінка
не гарантує безпеки: пропущені снаряди, зіткнення треків, прискорення й нові
атаки не входять до моделі.

Прогноз оцінює прямолінійний рух на короткому горизонті. На наступному кадрі
записаний гравець робить власну дію, а не дію алгоритму: тому успішний аналіз
запису не доводить, що бот зміг би пройти підземелля.

## Перевірка без гри

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe make_demo.py
.venv\Scripts\python.exe analyze.py demo.mp4 --output demo_annotated.mp4
```

Демо синтетичне. Воно перевіряє відеоконвеєр і прогноз для простих рухомих куль,
а не точність у RotMG. Наступний необхідний крок — калібрування на реальному
записі й ручна перевірка помилок детектора. Далі потрібні трекінг персонажа,
компенсація камери, розпізнавання фаз і лише після перевірки — керування WASD.

Джерело опису механік: https://www.realmeye.com/wiki/moonlight-village
(сторінка позначена WIP, останнє зазначене оновлення — червень 2025).
